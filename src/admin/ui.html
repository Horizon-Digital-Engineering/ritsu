Extensions

Connectors that give agents new jobs. Credentials are encrypted at rest and never shown to a model — agents act through them without ever seeing the secret. Turn an extension on for an agent with its capability checkbox (Agents tab).

✉️ Email —

IMAP (inbox) + SMTP (outbox) for any provider. Give an agent the crm capability and it can read the inbox and draft replies; sending always pauses for your approval. user/pass are shared between IMAP and SMTP.

𝕏 X / Twitter —

OAuth 1.0a from your X developer app (the 4 keys/tokens). Give an agent the social capability and it can read mentions + draft posts; posting always pauses for your approval. Reading needs the paid API tier; posting works on free.

in LinkedIn —

Publish-only (LinkedIn gives apps no feed read). Paste an OAuth 2.0 access token (scope w_member_social) and your author URN — urn:li:person:… for your profile or urn:li:organization:… for a company page. Shared social capability; posting always needs your approval.

Create / edit

Presets:
Who this agent can ask via mcp__agent_comms__ask_agent. Empty = no inter-agent calls.
manage_agents: agent can mint & edit other agents via mcp__agent_admin__*. monitor_agents: read-only swarm inspection via mcp__agent_monitor__*. crm: email manager — read inbox + send (sending always needs your approval). Configure the mailbox in the Extensions tab. Keep empty for normal agents.
Tools this agent must get your approval for before each use. The agent's turn pauses on a card in the Approvals tab until you approve or reject. Empty = no gating.
When on, a capability-escalation ask_agent call (this agent reaching one that holds a capability it lacks) goes to the Approvals tab instead of being hard-denied. Ignored for crm/social agents — those always hard-deny, since they read untrusted content. Leave off unless this is a trusted internal agent.

Test pane

Sends one turn using the current draft prompt + tools + (first) workspace. Response is billed but not saved as a conversation. Iterate on prompts without polluting history.

Filesystem workspaces

Each agent can be granted access to one or more filesystem paths. The lowest-id workspace becomes the agent's working directory; the SDK's built-in Read/Write/Edit/Bash tools operate from there. Permissions are recorded but enforced at the OS-user + cwd level in V0.3; per-tool permission checks land in V0.4.

API Keys

        

          Third-party model-provider keys (Anthropic, OpenAI, OpenRouter, local LiteLLM). Encrypted-at-rest with AES-256-GCM via the master key. Plaintext is shown once at mint time and never readable again. Agents that need a paid model reference one of these by id; Phase B wires the actual ritsu-agent runtime that uses them — for now the rows just sit here ready.

OAuth Clients

        

          Spec-compliant MCP clients (claude.ai web's "Add custom connector",
          Claude Desktop's Connectors UI) self-register here via
          POST /oauth/register (RFC 7591 Dynamic Client
          Registration). Public clients only — PKCE-required, no client
          secrets. Revoke from this view to invalidate the client AND all of
          its live access + refresh tokens at once (the cascade is automatic).

Admin action audit

        
Every mutating admin API call (POST/PATCH/DELETE) is recorded here for after-the-fact review. Reads (GETs) aren't logged — too noisy. Each row pins time, token used, IP, status, and a sha256 of the request body for tamper-evidence; hover the time cell to see the full timestamp + body hash.
